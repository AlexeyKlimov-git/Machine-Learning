# Backtest agent harness

## Задача

Превратить план эксперимента в проверяемый запуск: разрешенные инструменты,
ограничение времени, новый каталог артефактов, остановка на ошибке и отчет.
План может подготовить человек или LLM-агент. В проекте реализован исполнитель,
но нет встроенного LLM-планировщика и измеренной эффективности агента.

## Данные и вклад реализации

Публичный demo генерирует синтетические цены seed=42 и сравнивает buy-and-hold
с заранее фиксированной скользящей средней. Рабочих стратегий и данных нет.
Runner и demo написаны отдельно от закрытого бэктестера.

Локальные адаптеры следуют правилам пользовательских навыков backtest,
dibate2csv, diviz и diribbon. Самих навыков, бинарников, credentials,
снапшотов и закрытых конфигов в этой папке нет.
Публичная краткая памятка: skills/backtest-workflow/SKILL.md.

## Быстрый запуск

Только Python 3.11+, дополнительных библиотек не требуется.

```bash
python -m unittest discover -s tests -v
python -m src.runner examples/demo.json
python -m src.runner examples/demo.json --execute
python -m src.benchmark
```

Без --execute показывается план, но ничего не запускается.
Результаты: artifacts/<run-id>/summary.json и 0/metrics.json.
Benchmark сравнивает 5 прямых запусков и 5 запусков через harness, проверяет совпадение результатов.
Это накладные расходы обертки, НЕ экономия труда исследователя и НЕ оценка LLM.

## Подключение локального бэктестера

Заполняйте только личные local*.json, исключенные из Git. Нужны установленные
и разрешенные вам инструменты. Пути в шаблоне — placeholders.
Не переносите рабочие данные в репозиторий.

```bash
python -m src.runner local-plan.json
python -m src.runner local-plan.json --execute --allow-local-tools --binaries local-binaries.json
```

local-binaries.json — map: backtest/dibate2csv/diviz/diribbon → абсолютный путь к вашему executable.
Образец плана: examples/local-plan.template.json.
После backtest создайте следующий план для dibate2csv с args.input равным полученному
.dibate и args.from/to равными заказанному периоду. Проверяется Start/End (допуск 60 с).
Для diviz достаточно args.input. Для diribbon — args.input (каталог только выбранных файлов)
и capital_mode. Итог всегда вне каталога входов.

Связи между шагами задаются явно: автоматической подстановки output предыдущего шага нет.
План из LLM обязательно проверяет человек; runner не является sandbox.
local-провайдер может скачать недостающие данные: он не гарантирует офлайн-режим.
Credentials и произвольные CLI-флаги через план не принимаются.
Stdout/stderr локальных инструментов не сохраняются, чтобы не утекли внутренние адреса.

## Baseline, проверки и ограничения

Фактические измерения: reports/RESULTS.md.
Тесты: пустой результат при exit=0, остановка цепочки, повторное использование старой папки,
неявное разрешение локальных инструментов, отсутствие timezone и обрезанный период.

Коммерческие инструменты здесь не запускались; их адаптеры проверяются unit-тестами.
Массовый stats_calc намеренно не включен в исполнитель: для него нужны отдельная
валидация parquet, обработка частичных ошибок se и ограничение ресурсов.
Навык stats_calc изучен; не подменяем интеграционный тест фиктивной «успешностью».

Для измерения пользы агента нужен отдельный benchmark из одинаковых задач:
manual vs agent-assisted, время до проверенного результата, success rate,
число правок и стоимость. Эти показатели пока не измерены.
