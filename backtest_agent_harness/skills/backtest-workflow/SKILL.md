# Проверяемый backtest workflow

Публичная памятка, подготовленная по правилам локальных навыков.
Не содержит их исходный текст, инфраструктурные адреса или данные.

1. До запуска согласовать период, входные данные, стоимость сделок и критерий оценки.
2. Выделить новый выходной каталог; старый результат не является успехом нового запуска.
3. Один конфиг — backtest; пакет требует отдельной обработки частичных ошибок.
4. Не считать exit=0 доказательством успеха: проверить непустой артефакт.
5. Для чисел вызвать dibate2csv в одном режиме statistics и проверить фактические Start/End.
6. Для картинки использовать diviz и проверить PNG.
7. При склейке diribbon подавать только выбранные файлы; выход держать вне входной папки.
8. Режим капитала фиксировать заранее, не выбирать по лучшему результату.
9. Не интерпретировать внутренний Sharpe как годовой без проверки определения.
10. Не публиковать локальные бинарники, торговые конфиги, snapshots и отчеты.

Агенту: предложи JSON-план, объясни проверки и остановись перед запуском.
Не ищи credentials, не меняй торговые системы и не запускай реальную торговлю.
